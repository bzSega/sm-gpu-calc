# GPU Calc Playground

Отдельный экспериментальный интерфейс на общем ядре GPU Calc.
Текущий калькулятор в `../simulation.html` продолжает работать независимо.
Playground не включён в `distr/` и список файлов публикации. Адрес будущей
публикации пока не выбран.

## Три мира

Сохраняем все три направления как разные оформления одной симуляции:

1. **Серверная** — узнаваемые стойки, люди за компьютерами, входящие запросы,
   очередь и ответы. Основной акцент — связь с настоящей инфраструктурой.
2. **Вычислительная мастерская** — стойки на рабочих местах, открытые корпуса,
   выдвижные карты. Основной акцент — сборка и объяснение устройства.
3. **Орбитальная станция** — светлый научный отсек с настоящими серверными
   стойками. Основной акцент — исследование и более игровой мир.

Общий визуальный ориентир: [моки трёх миров](assets/worlds-concept.png).
Изображение создано встроенным генератором изображений для выбора направления;
это концепт, не точная схема GPU и не готовый игровой спрайт.

## Общий маршрут

Главное меню → пустая стойка → установка GPU → выбор модели → открытие
сервиса → первые люди → рост потока → расширение инфраструктуры.

Игровой интерфейс с первого экрана. Без play/pause и таймлайна: сервис
работает непрерывно, игрок меняет приход новых пользователей. Мир выбирается
в настройках и не меняет расчёты. Живая сессия ещё не реализована.

- Пользователи отправляют запросы; конверты обозначают запросы, не людей.
- Несколько GPU совместно хранят и исполняют одну копию модели.
- Дополнительная копия — отдельная группа карт с собственными весами и KV.
- Веса остаются в памяти; KV выделяется активным запросам и освобождается.
- Активные запросы и занятый KV показываем раздельно. Очередь возможна при
  почти свободной памяти. Индикатор мест обработки не означает GPU utilization.
- Движение и эффекты показывают состояние расчёта, а не создают новые события.
- Нет лозунгов, искусственных очков производительности и декоративных цифр.

## Граница кода

`index.html` — стартовая страница разработки: переключает миры, показывает
сохранённый концепт и выполняет контрольный расчёт на настоящем общем ядре.
Игровой сцены, настройки и воспроизведения в этом подпроекте пока нет.

Подключаем `../sim-core.js` и `../scenario-core.js` напрямую. Не копируем ядра,
пресеты и формулы в этот каталог. Оформление мира не входит в расчётные параметры.
Для игры потребуется общий пошаговый событийный движок: текущий конечный
`SimCore.simulate` пока не поддерживает изменение работающей сессии.
Формулы не дублируем; совместимость текущего калькулятора сохраняем.
Контракт и ограничения: [UNIFIED-SCENARIO](../docs/UNIFIED-SCENARIO.md).

Локальный запуск из корня репозитория:

```sh
python3 -m http.server 8030
# http://127.0.0.1:8030/playground/?world=server-room&lang=ru
```

Миры: `server-room`, `workshop`, `orbital`. Языки: `ru`, `en`.
При будущей отдельной поставке оба общих ядра должны входить в её комплект;
текущий семифайловый релиз менять для этого не нужно.

## Следующая итерация

Нарисовать каждый мир отдельно с одинаковыми состояниями: простой, работа,
очередь из-за лимита активных запросов, ожидание памяти. Затем собрать общую
сцену и приближение к стойке; управление сервисом должно работать одинаково
во всех трёх мирах. Текущий симулятор до этого не заменяем.
