# PRD: SM GPU Calc

_Рабочая версия · 2026-09-29. Реализованный контракт: [UNIFIED-SCENARIO.md](UNIFIED-SCENARIO.md); будущие возможности ниже не являются текущими._

## 1. Задумка

**Проблема.** Планируя инфраструктуру LLM-инференса (свой кластер, аренда GPU, нагрузка от
агентных пайплайнов), инженер и продукт не могут быстро ответить на вопросы:
«Сколько нужно GPU под эту нагрузку?», «Какой будет TTFT и длина очереди?»,
«Что дороже — аренда пула или pay-per-token у провайдера?» Существующие калькуляторы
либо считают абстрактные токены, либо требуют вручную строить модель очередей в таблице.

**Решение.** Единый симулятор нагрузки LLM на одном переиспользуемом
расчётном ядре. Всё работает офлайн (статика, без бэкенда): открыл HTML — получил расчёт.

**Принципы:**
1. **Одно ядро — много оболочек.** `sim-core.js` (JavaScript-ядро, без DOM) используется
   страницами, будущим CLI и MCP-сервером одинаково.
2. **Три режима достоверности, чётко разделённые в UI:**
   - *учебная оценка* — грубые формулы, для интуиции;
   - *сценарная симуляция* — дискретно-событийная очередь на реальном трейсе;
   - *калибровка бенчмарками* — подстройка профилей по vLLM bench serve и т.п.
   Симуляция не должна «выглядеть точной, потому что красиво считает» — источники и
   допущения показываются явно.
3. **Реальные данные важнее синтетики.** Демо-трейсы собираются из настоящих агентных
   пайплайнов (обезличенных), формат — `requests.csv` (§5).

## 2. Пользователи и сценарии

| Кто | Сценарий |
|---|---|
| Инженер / SRE | Прикинуть размер пула под RPS и контекст, увидеть узкое место (prefill vs decode) |
| Продакт / автор агента | Оценить стоимость прогона агентного пайплайна (DAG вызовов) на разном железе |
| Преподаватель / контент | Наглядно объяснить очередь, TTFT, экономику инференса |
| Себя (SM) | Фаза 1.5: гонять реальные трейсы OpenClaw и считать экономику своих продуктов |

## 3. Что уже есть

- **simulation.html** — единый интерфейс: нагрузка → очередь → реплики → GPU-память → результат.
- **sim-core.js** — FIFO, параллельные запросы с учебной кривой скорости, допуск по KV,
  события prefill/decode, TTFT, очередь и стоимость аренды. 24 семантических теста.
- **scenario-core.js** — общий каталог сценарных профилей, память, CSV и JSON.
- Воспроизведение и раскрытие стойки, сравнение с вариантом A, экспорт CSV/JSON.
- **examples/trip-moscow-nizhny/** — воспроизводимый пример формата; происхождение
  токенов указано в manifest. Зависимости DAG не исполняются симулятором.
- **scripts/release.sh** — синхронизация distr → тесты → рендер → ZIP с версиями JS.
- Поставка: index.html, simulation.html, два JS и VERSION.txt; file://, RU/EN.

## 4. Дорожная карта

**Фаза 1.5 — захват реальных трейсов OpenClaw** (следующая)
Хук/скрипт, пишущий вызовы модели из живой сессии (`provider_usage`, а не proxy_estimate)
в `requests.csv`; прогон реального трейса через ядро; обновление демо-примера телеметрией.

**Фаза 2 — достоверность и сравнение**
- профили бенчмарков (vLLM bench serve → калибровка ток/с);
- расширение реализованного сравнения с вариантом A;
- CLI (`npx sm-gpu-calc simulate trace.csv`) на том же ядре;
- экономика: pay-per-token эквивалент рядом с арендой пула;
- источники и даты для редактируемых цен GPU и сценарных профилей.
  Реплика — копия модели на выбранном числе GPU, не обязательно одна нода.

**Фаза 3 — распределение и интеграции**
- DAG-зависимости запросов в симуляции (сейчас depends_on игнорируется);
- локальный MCP-сервер: validate / simulate / compare / export;
- при росте — разнести на пакеты (ядро / страница / CLI / MCP).

## 5. Формат данных (канон)

`requests.csv`: `request_id, arrival_ms, input_tokens, output_tokens` — обязательные;
`model_profile_id, token_count_source, job_id, depends_on` — метаданные, игнорируются ядром.
Валидация: уникальные ID, целые ≥ 0 (output ≥ 1), ≤ 10 000 строк, ≤ 2 МБ.

## 6. Не делаем (non-goals)

- Точный расчёт KVC/paging/batching глубже учебной модели — не претендуем;
- Сетевой бэкенд, аккаунты, телеметрия пользователей — проект полностью локальный;
- Замена реального нагрузочного теста — только планирование и интуиция.

## 7. Риски и открытые вопросы

- **Хостинг/деплой:** статическая поставка на mikhaylov.com/gpu-calc; загрузка полного
  ZIP пользователем. JS версионируются по содержимому для защиты от старого кэша.
- Цены GPU и профили моделей — экспертные оценки до Фазы 2 (калибровка).
- Прирост скорости от параллельности требует калибровки по измерениям.

## 8. Метрики успеха v1

- Инженер получает ответ «сколько GPU и что будет с TTFT» за < 2 минут без чтения доков;
- Реальный трейс OpenClaw прогоняется end-to-end без ручных правок CSV;
- Тесты + E2E зелёные на каждый релиз; релиз = одна команда.
