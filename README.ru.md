# SM GPU Calc

**Нагрузка LLM → очередь → GPU-реплики → память, задержки и стоимость.**

[Открыть калькулятор](https://mikhaylov.com/gpu-calc/?lang=ru) · [English](README.md) · **Русский**

`MIT` · `HTML / CSS / JavaScript` · `Статический хостинг` · `RU / EN`

Интерактивный учебный симулятор GPU-инференса. Помогает понять, как поток запросов,
параллельная обработка и KV-память влияют на очередь и задержки. Расчёты выполняются
в браузере; профили моделей и кривые скорости — допущения, а не бенчмарки.

### Нагрузка и GPU-пул

Запустите воспроизведение или перемещайте ползунок: на репликах видны активные
запросы, занятая и свободная память под KV. На скриншотах интерфейс на английском;
в калькуляторе язык переключается кнопкой **RU**.

![Симуляция: GPU-реплики, KV-память, очередь во времени и результаты](docs/screenshot-unified.png)

### Внутри реплики

Раскройте реплику: веса, резерв KV, резерв среды и свободная память показаны
на каждой GPU. Воспроизведение доступно прямо в стойке.

![Стойка: память каждой GPU и синхронное управление воспроизведением](docs/screenshot-unified-rack.png)

### Что умеет калькулятор

- **Нагрузка:** готовый пример, ручной равномерный поток или импорт CSV.
- **Оборудование:** профиль модели, H200/B200, 1–16 GPU на реплику и 1–8 реплик.
- **Параллельность:** 1–256 активных запросов на реплику с явным допущением о приросте общей скорости.
- **Память:** каждый активный запрос резервирует KV. Если нет места или свободного слота, запрос ждёт; после завершения память освобождается.
- **Воспроизведение:** prefill/decode, очередь, завершённые запросы и свободная память меняются по времени. В стойке доступны свои синхронные элементы управления.
- **Результаты:** длительность, пиковая очередь, TTFT p95, аренда за весь прогон и стоимость запроса.
- **Сравнение и экспорт:** вариант A, результаты CSV, сохранение и повторный запуск JSON-сценария.

**Реплика** — одна копия модели, распределённая между её GPU. Восемь карт внутри
реплики совместно обрабатывают запросы этой модели.

### Быстрый старт

```sh
python3 -m http.server 8000 --directory distr
```

Откройте [localhost:8000](http://localhost:8000/) или сам файл `distr/index.html`.
Для открытия файла рядом должны лежать `sim-core.js` и `scenario-core.js`.
Установка npm, серверная часть и собственная GPU не нужны.

**«Пример»** загружает 24 синтетических запроса через каждые 200 мс.
**«Задать»** позволяет указать число запросов, частоту поступления и длину входа/ответа.
**«↑ CSV»** открывает файл в формате из раздела ниже. RPS — запросов в секунду
на входе, а не скорость ответов. Реальные тексты в модель не отправляются:
симулятор работает с количеством токенов. Файлы обрабатываются в браузере.

### Формат CSV

```csv
request_id,arrival_ms,input_tokens,output_tokens
r1,0,10000,1000
r2,200,10000,1000
r3,400,5000,500
```

`arrival_ms` — время от начала сценария в миллисекундах. Все четыре столбца
обязательны. ID должны быть уникальными; время поступления и число токенов —
целыми, вход ≥ 0, выход ≥ 1. Лимит: 10 000 запросов и 2 МиБ на CSV.
Парсер не поддерживает поля в кавычках и многострочные поля. Дополнительные
метаданные сохраняются, но зависимости между запросами не влияют на выполнение.

### Как читать цифры

- Скорости prefill/decode заданы для одного запроса на **всей реплике**.
- Параллельные запросы делят скорость. Прирост 0% сохраняет общую скорость,
  100% предполагает идеальное линейное ускорение; начальные 50% — учебное допущение.
- «KV занято» — резерв под полный вход и ответ активных запросов. «KV свободно» —
  оставшийся бюджет после весов, резерва среды и активных KV-резервов.
- Свободная память меняется при старте и завершении запросов. Рост кэша по токенам
  и повторное использование общего префикса пока не моделируются.
- Вместимость по памяти рассчитана для самого длинного запроса. Она не гарантирует
  такое же число пользователей с приемлемой задержкой.
- Причина очереди относится к ограничениям симулятора; физическое узкое место GPU
  и реальную скорость конкретной модели нужно определять по замерам.

Профили моделей и кривая скорости — **сценарные допущения, не бенчмарки**.
Нет chunked prefill, модели межсоединений, вытеснения и исполнения DAG. Аренда
включает все GPU от начала сценария до последнего завершения, в том числе простой.
Подробности: [формулы, форматы и ограничения](docs/UNIFIED-SCENARIO.md).

### Передача настроек

URL поддерживает параметры `lang`, `model`, `gpu`, `replicas`, `cards`, `prefill`,
`decode`, `price`, `reserve`, `concurrency` и `batchGain`. Ключи моделей: `glm53`,
`flash`, `qwenflash`. Параметр `progress=0..1` выбирает момент прогона,
`drill=1` раскрывает реплику.

```text
index.html?lang=ru&model=glm53&gpu=B200&replicas=2&cards=8&concurrency=8&batchGain=50
index.html?lang=ru&progress=0.5&drill=1
```

URL содержит настройки, но не импортированные запросы. Чтобы воспроизвести свою
нагрузку, сохраните JSON-сценарий. Старые сценарии `/1` открываются с одним активным
запросом на реплику; новые сохранения используют `/2`.

### Публикация

Запустите `bash scripts/release.sh` и загрузите на хостинг **весь полученный ZIP**
из `releases/`. Скрипт проверит ядро и рендер, синхронизирует дистрибутив и обновит
версии JS в ссылках, чтобы старый браузерный кэш не ломал новую страницу.
Для сборки нужны Node.js, Python 3 и Chrome. Автоматической публикации нет.

## Репозиторий

| Путь | Назначение |
| --- | --- |
| `simulation.html` | Единый интерфейс |
| `sim-core.js` | FIFO, распределение скорости и допуск по KV-памяти |
| `scenario-core.js` | Профили, память, CSV и JSON |
| `distr/` | Статическая поставка; `index.html` и `simulation.html` идентичны |
| `tests/sim-core.test.js` | Тесты ядра и сценариев |
| `scripts/release.sh` | Проверки, версии ресурсов, дистрибутив и ZIP |
| `scripts/render-check.sh` | Скриншоты Chrome и проверка ошибок выполнения |
| `docs/UNIFIED-SCENARIO.md` | Контракт расчёта |
| `docs/PLAN.md` | План развития |
